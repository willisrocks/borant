# Borant v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Borant v1: a Rust messaging, task, and agent-mobility system for coding-agent harnesses, with a hub daemon, host daemons, a CLI, a Claude Code plugin, a Pi and omp extension, and Docker multi-host tests.

**Architecture:** Hexagonal. `borant-core` holds the domain types, the rules, and the port traits, with no I/O. Adapter crates implement the ports (memory for tests, NATS for production). `borant-hub` and `borant-host` are services that are generic over the ports. The `borant` binary wires adapters into the services and adds the CLI, the MCP server, and the hook handlers.

**Tech Stack:** Rust 1.96 (edition 2024), tokio 1.54, async-nats 0.50, axum 0.8, hyper 1.12, rmcp 3.7, clap 4.6, serde 1.0, jsonschema 0.60, rusqlite 0.40 (bundled), sysinfo 0.39, ulid 3, tracing 0.1. TypeScript for the Pi and omp extension. Docker Compose for multi-host tests. NATS server 2.11 or later in Docker.

**Spec:** `docs/superpowers/specs/2026-10-24-borant-design.md` (sections cited as "spec §N")

## Global Constraints

- All Borant binaries are Rust. The Pi and omp extension is one TypeScript file. (spec §3)
- Ports must not expose NATS types or NATS behavior. (spec §6)
- Adapters are compile-time crates behind Cargo features `nats` and `memory`. (spec §6)
- Only the hub daemon writes control-plane keys. (spec §6)
- Identifier rule for agent IDs, channel names, and host names: `^[a-z0-9][a-z0-9_-]{0,62}$`. They appear in NATS subjects and KV keys, so dots, spaces, `*`, and `>` are invalid.
- Defaults: heartbeat 10 s, lease 30 s, grace period 2 min, claim timeout 30 min, wakes 30 per hour, session log 50 turns, tool output 8 KB per event, message text 64 KB, message retention 30 days. (spec §10, §11, §12, §19)
- Local API: Unix socket `$BORANT_HOME/host.sock`, mode 0600. `BORANT_HOME` defaults to `~/.borant`. (spec §6)
- Hooks and the extension must never break the harness: if the daemon is down, they exit 0 with no output within 2 s.
- Launched sessions run with permission prompts off (`claude --dangerously-skip-permissions`). (spec §15)
- Outside CI, run only focused tests (`cargo test -p <crate> <filter>`). The full suite runs in CI. (user rule)
- Lints: `unsafe_code = "forbid"`, clippy with `-D warnings` in CI, rustfmt default style.

## Review Focus

1. The host daemon is not running when a hook or the extension runs. Expected: the harness works as if Borant were absent. Test in Task 14.
2. The hub is unreachable at session start. Expected: the session works without Borant tools, the daemon retries registration, and the agent gets its tools when the hub returns. Test in Task 10.
3. A user gives an agent ID or a channel name with a dot, a space, `*`, `>`, or uppercase letters. Expected: a clear validation error that names the rule. Test in Task 2.
4. A tool result or a message is larger than the NATS payload limit (1 MB). Expected: session events cut at 8 KB with a marker, and messages over 64 KB rejected with an error. Test in Task 3 and Task 10.
5. The clocks of the hosts differ. Expected: lease expiry uses the hub clock only, and a host pauses its sessions by a monotonic timer since the last successful heartbeat. Test in Task 10.
